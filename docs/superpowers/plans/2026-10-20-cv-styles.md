# CV Styles (RenderCV) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** RenderCV renders every CV PDF in every mode. The owner picks, tunes, and uploads named styles in a new admin
screen with a live preview, and the default is compact.

**Architecture:**

- **Shared renderer module:** one Python module (`services/cv-render/cvrender.py`) turns site CV data plus a style into
  RenderCV input and renders it. It is shared by the GitHub Actions script (git and static modes) and by a private
  Python service deployed beside Astro with Vercel Services (git and postgres modes, for previews and the postgres
  public PDF).
- **TypeScript client:** a small client (`src/lib/cv-render.ts`) calls that service through a binding, or spawns the
  module locally under `astro dev`.
- **Styles and pdfmake:** styles live in `config/cv-styles.yml`. Custom themes live under `cv/themes/<name>/`. pdfmake
  is deleted.

**Tech Stack:** Astro 5, Vue 3 admin, TypeScript (`node:test`), Python 3.12+, RenderCV 2.8 (Typst, no TeX), Vercel
Services.

**Spec:** `docs/superpowers/specs/2026-10-20-cv-styles-and-job-search-design.md` (Project 1, and "Decided after
review").

## Global Constraints

- **RenderCV:** pin `rendercv[full]==2.8` everywhere (the service's `requirements.txt` and `scripts/requirements.txt`).
  Python ≥ 3.12.
- **No new npm dependencies.** Remove `pdfmake` and `@types/pdfmake`.
- **Design keys are RenderCV's own snake_case names, stored verbatim.** Never run them through the camelCase
  converter.
- **Custom theme names** match `^[a-z0-9]+$` (RenderCV's rule) and must not equal a built-in theme name. Files:
  - only `*.j2.typ` or `*.typ`
  - every path segment matches `^[A-Za-z0-9_][A-Za-z0-9_.-]*$`, with no `..`
  - at most 40 files and 512 KB total
- **Theme uploads and deletes are publisher-only** (`assertPublisher`, `src/lib/admin/editor.ts:416`). Theme templates
  are Jinja and run inside the renderer.
- **A failed render never replaces the public PDF.** The last good `cv.json`/PDF stays, and the error text (RenderCV's
  message) reaches the admin.
- **Precedence:**
  - **Upload:** a raw upload (`cv-upload.yml`, `enabled: true`) carrying its own `design` is rendered with that design.
    Otherwise the selected style's design is used.
  - **Design layers:** theme defaults, then the density preset, then the style's `design` overrides (the last one
    wins).
- **Font spans** (`[text]{.mono}`) are stripped to plain text in every PDF (the existing `strip_site_markup`).
- **Python tests** are assert-based self-check scripts run with `python3 <file>`, matching `scripts/test_render_cv.py`.
  **TypeScript tests** use `node:test`, run with `pnpm test`.

## Review Focus

1. **Bad design value.** A style with an invalid value (`top_margin: abc`) shows RenderCV's error in the preview and on
   save, and the public PDF and `cv.json` stay unchanged. This is pinned in Task 4 (`generate keeps the last PDF when
   the renderer fails`).
2. **Author bolding.** The pdfmake PDF bolded `site.author` in publication author lists, and RenderCV doesn't. That
   regression must not ship. Pinned in Task 1 (`bold_author`).
3. **Raw upload with or without its own `design`.** It must follow the precedence rule above. Pinned in Task 1
   (`build_input upload precedence`).
4. **Hostile theme upload.** `../x.j2.typ`, `__init__.py`, the name `classic`, a 2 MB file: each is rejected with a 400
   before anything is committed. Pinned in Task 3 (`assertThemeFiles rejects`).
5. **The public style is deleted or renamed.** `parseStyles` must still return a valid `public` (the first style), and
   an empty or garbled file falls back to the defaults. Pinned in Task 3 (`parseStyles repairs public`).

  uses it under `astro dev`.
